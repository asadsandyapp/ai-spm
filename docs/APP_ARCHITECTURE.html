AI-SPM

Application Architecture

The application shape we follow — layers, technologies, packages, and how console, gateway, and endpoint agent fit together.

Purpose. This document defines the application architecture for AI-SPM: which major components exist, which technologies and packages we use in each layer, and how responsibilities are split. New features should reuse this structure rather than introducing parallel stacks or frameworks.

1. Architecture we follow

AI-SPM is a hybrid endpoint + central multi-tenant gateway application:

  1. Endpoint agent (Rust) runs on the managed PC — enrolls, intercepts AI traffic, talks to the gateway over mTLS.
  2. Security core (Python FastAPI) runs policies, PII/threat inspection, audit, quotas, and admin/platform business logic.
  3. Admin & platform consoles (React SPA) are the human UI for company and vendor operators.
  4. Edge (Kong) is the secure front door; Postgres + Redis are the durable store and cache.

3. Backend package layout (ai_spm)

All backend code lives under backend/src/ai_spm/. We keep a clear ownership split:

Package / area Responsibility
admin/Company admin HTTP surface
agent/Endpoint agent HTTP surface (register, heartbeat, prompt, updates)
platform/Vendor platform surface + provisioning (metadata only)
public/Unauthenticated onboarding (signup / verify)
billing/Stripe webhook and subscription helpers
services/Business orchestration — prompt pipeline, policy, audit, enrollment, dashboard
domain/SQLAlchemy models and enums
infrastructure/Adapters: DB, Redis, Presidio, Guardrails, LLM client, auth/password
tenant/TenantContext, middleware, RLS, quotas
jobs/APScheduler periodic work
presentation/Correlation ID, WebSocket helpers

Layering rule we follow

  • Routes — parse request, auth dependency, call a service, map errors. No business logic.
  • Services — own the workflow (pipeline order, policy evaluation, audit writes).
  • Domain — persistence shapes only.
  • Infrastructure — external systems (scanners, cache, email, DB session). Do not duplicate domain rules here.
Request through the application ─────────────────────────────── Client → Kong → middleware stack → route handler → service → adapter / Postgres (RLS) → JSON response Middleware order (fixed): CORS → Correlation ID → Quota → Org-id body guard → TenantContext

5. Endpoint agent (Rust workspace)

Runtime stack: Tokio async runtime, hyper HTTP, rustls for mTLS. Linux enterprise install uses systemd (ai-spm-agent), transparent redirect for AI traffic, CA trust, and mitmproxy for consumer web UIs. Packaging: sealed Linux .run from Admin Download Agent; Windows path via service + WiX MSI.

7. Data & tenancy packages

  • ORM / migrations: SQLAlchemy 2 async + Alembic
  • Driver: asyncpg
  • Isolation: JWT org_id → TenantContext → query filters → PostgreSQL RLS (aispm_app / app.current_org_id)
  • Auth helpers: bcrypt passwords; separate tenant and platform JWT secrets
